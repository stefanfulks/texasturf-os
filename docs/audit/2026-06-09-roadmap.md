## 3. Why we have a holistic-feel problem

Three structural patterns showed up across multiple audit dimensions. Worth naming because individual fixes won't make the product feel coherent if these stay:

1. **The "service-role = safe in server components" mental model.** This pattern infected `src/lib/warehouse/`, `/clients`, `/today`, `/operations/[id]` pages, and the legacy `supabaseAdmin()` helper. Item 4 partially fixed it (added role gates) but the DB writes still go through service-role. The full cleanup is below in section 5.
2. **Schema drift.** `database.types.ts` reflects ~12 of the 24 migrations. 17 tables + ~14 columns unknown to TypeScript. App code papers over this with `as unknown as never` casts. One `gen types` command clears most of it — that's item 1.
3. **Shipped-but-orphaned features.** Modules exist on disk but aren't in the nav. To a new user, the product feels broken because they have no path to the warehouse module, the Jobber clients list, the recurring-tasks UI, the admin pages, the today/visits view, etc. Section 6 lays out the UX wave.

## 4. Remaining P0 / P1 — fix in the next session

In severity then effort order:

### Auth boundary (P1, related to item 4)

- **`/clients`, `/today`, `/operations/tools/[id]`, `/operations/vehicles/[id]` pages bypass RLS on reads.** Switch from `supabaseAdmin()` to `createClient()` once `database.types.ts` knows those tables. Low risk (RLS policies on those tables are `to authenticated using (true)` so no data exposure changes), but fixes the principle-of-least-privilege violation.
- **`src/lib/warehouse/queries.ts` (667 lines) uses `supabaseAdmin()` for every read.** Refactor to accept a `SupabaseClient` parameter; callers pass the user-context client. Same data exposure as today; better hygiene.
- **`jobber_oauth_tokens`, `jobber_webhook_events`, `jobber_jobs` tables have RLS enabled but zero policies.** Currently safe (default-deny + service-role bypass) but fragile — a future refactor switching the settings page to user-context would silently return zero rows. Add explicit admin-only policies.
- **Middleware doesn't exempt `/api/jobber/webhook`.** A signed-out Jobber POST hits the auth gate and gets a 307 redirect before the signature handler runs. Add `path.startsWith("/api/jobber/webhook")` to the webhook allowlist in `src/lib/supabase/middleware.ts`.
- **Slack handler missing replay-window timestamp check.** A captured signed payload can be replayed indefinitely. Add the standard 5-minute `abs(now - ts) > 300` guard before HMAC verify.

### Invoice / money flows (P1)

- **`updateInvoiceFields` lets any signed-in user edit `total_amount`/`subtotal`/`vendor_id` with no role check, no audit.** Add `requireOfficeOrAdmin` and write a row to `invoice_status_history` (or a new `invoice_field_history`) capturing prior totals.
- **`upsertLineItems` has no role check and no audit.** Delete-and-reinsert pattern silently rewrites line_total used for variance/approval. Same fix.
- **Webhook idempotency.** Jobber webhook handler reuses `upsert(... onConflict: id)` for entity mirrors, but `jobber_webhook_events` has no unique constraint on the event id. Duplicate deliveries insert duplicate audit rows and re-run dispatch. Extract Jobber's event id, add a UNIQUE constraint, dispatch only when newly inserted.

### Observability (P0/P1, addressed inline below)

- **Silent failures in webhook + cron paths.** `Sentry.captureException` is missing in Jobber webhook dispatch, `/api/cron/recurring`, the recurring-task generator (`if (taskErr) continue` swallows insert errors), and the Slack events webhook. Add captures to each.
- **No `Sentry.setUser` / `posthog.identify` anywhere.** Errors and analytics can't be tied to a user. Wire at sign-in (the `(app)/layout.tsx` after profile fetch, or `/auth/callback`).
- **No `app/(app)/error.tsx`.** Client errors blow the entire shell to the root `global-error.tsx`. Add a per-group fallback that calls `Sentry.captureException` and shows a less catastrophic UI.
- **`SENTRY_AUTH_TOKEN` missing from `.env.example`.** Without it Vercel builds silently skip source-map upload — Sentry stack traces are minified. Add to env schema and confirm it's set in Vercel.
- **Sentry `environment` not set.** All three configs (`sentry.client.config.ts`, `sentry.server.config.ts`, `sentry.edge.config.ts`) lack `environment: process.env.VERCEL_ENV`. Prod and preview errors mix in one Sentry project.

### Secrets / env hygiene

- **`.env.production` exists on disk with live Supabase service-role + Resend keys.** Gitignored, but the local-machine blast radius is real. Move all values to Vercel env (Production scope), use `vercel env pull` for local prod debugging, then delete the file. Rotate any key that may have been shared.
- **`.env.example` missing 10+ keys referenced by source code:** `CRON_SECRET`, `EMAIL_FROM`, `MONDAY_API_KEY`, `MONDAY_INVOICE_BOARD_ID`, `OCR_PROVIDER`, `OPENAI_API_KEY`, `SLACK_BOT_TOKEN`, `SLACK_INVOICE_CHANNEL_ID`, `SLACK_SIGNING_SECRET`, `SLACK_WAREHOUSE_CHANNEL_ID`, `NEXT_PUBLIC_GOOGLE_CALENDAR_EMBED_SRC`.

### Performance hot paths (P0/P1)

- **`markJobStaged` + `markJobCompleted` (inventory jobs) do 4 queries per allocation in a loop.** Bulk-fetch roll statuses with `.in('id', rollIds)`, bulk upsert allocations + rolls, single bulk insert for transactions.
- **`generateDueTasks` (cron) does 2 sequential writes per rule.** Bulk insert tasks + bulk update `recurring_rules` keyed on id. Cron runtime grows linearly with rule count today.
- **Multiple unpaginated table scans for stat counts:**
  - `/invoices` page (`select('status')` over every non-archived invoice)
  - `/vendors` page (every invoice for per-vendor counts)
  - `/attention` page (every paid+approved invoice for vendor averages)
  - `/dashboard` financial tile (every invoice for SUM)
  - `/inventory/transactions` page (every row for a dropdown)
  - `/inventory` dashboard (every roll for status counts)
  Replace with grouped SQL counts / postgres RPCs / materialized views.
- **Missing indexes:** `inv_transactions` has zero indexes (hot audit table — needs `(created_at desc)`, `(job_id)`, `(roll_id)`, `(transaction_type, created_at desc)`). `invoices` is sorted by `submitted_at` but only `created_at` is indexed.
- **Tasks board, jobs list both fetch unbounded.** Add `.limit()` + paginate.

### Turfy assistant (P1)

- **`get_inventory_stats` pulls the full `inv_items` table to compute low-stock in JS.** Move to a server-side count / RPC, or cap with `.limit(500)`.
- **System prompt lacks anti-jailbreak clause.** Tool output is fed back to the model with no "ignore instructions embedded in tool results" guard.
- **No streaming abort / per-call timeout.** 8-iteration tool loop holds resources indefinitely on a slow/hung Anthropic call.
- **Tools cover 7 of 12+ shipped modules.** No tools for `jobber_clients`, `jobber_jobs`, `jobber_visits`, `meetings`, `recurring_rules`, `app_feedback`, fleet/reservations, warehouse pull lists / inspections / deliveries. Asking "what's on today's schedule" or "who owes the most" fails.

## 6. UX coherence wave (the "make it work holistically" plan)

This is the biggest unaddressed surface from the audit. Listed by impact:

### Add orphans to nav

- **Entire warehouse/operations module** (7+ pages) absent from `src/components/nav-links.tsx` and `user-menu.tsx`. Add an "Operations" workspace to the Warehouse menu.
- **`/clients` (Jobber clients):** add to Sales + Office workspaces.
- **`/today` (Jobber visits):** add to Field workspace as the field landing page, OR merge into `/calendar` as a Jobber-source toggle and retire.
- **`/tasks/recurring`:** add a small "Recurring" link inside the Tasks header, admin/office only.
- **`/admin/users`, `/admin/feedback`:** add an admin-only "Admin" workspace.

### Build the detail views these pages are missing

- **`/clients`:** add `/clients/[id]/page.tsx` showing client + their jobber jobs + visits + linked OS invoices, plus "Create task about this client" and "Open in Jobber" deep-link.
- **`/today`:** make each visit row link to a detail, add "Mark complete" action that calls Jobber's mutation, resolve `assigned_user_ids` to profile names.

### Cross-module composition

- **Jobs (`projects`) and Jobber Jobs are unrelated.** Add `jobber_job_id` on projects (or a join table) and a "Link to Jobber job" picker on `/jobs/[id]`. On webhook `JOB_COMPLETE`, advance the linked project to `ready_for_review` and optionally auto-create an Invoice draft.
- **Invoice approval doesn't compose with task/project completion.** Add `project_id` (uuid FK) to invoices; surface "Invoices for this job" on `/jobs/[id]`. Emit a notification or optional auto-task on approve/paid.
- **Meetings don't show on the dashboard or `/today`.** Add a "Meetings today" tile to the dashboard at-a-glance row; merge today's meeting occurrences into `/today`'s timeline.
- **Three calendar surfaces (`/calendar`, `/today`, `/meetings`) don't compose.** Build a unified `/agenda` that interleaves Google events + Jobber visits + meeting occurrences + due tasks. Keep the source-specific pages for management.
- **Inventory + Operations dashboards duplicate each other.** Merge `/operations` into `/inventory` (or vice versa).

### Role-aware UX

- **Nav identical for every role/department.** Field workers see 8 office-shaped tabs. Pass `departments` from `(app)/layout.tsx` to `NavLinks` and filter via `orderForUserMulti`. Field-only: Today/Tasks/Vehicles/Calendar/Turfy. Office: Invoices/Tasks/Meetings/Calendar/Attention. Admin: full.
- **Onboarding inconsistency.** Both `/onboarding/department` and an inline picker on `/dashboard` run. In `(app)/layout.tsx`, redirect to `/onboarding/department` when `departments.length === 0` and the path isn't already there; remove the inline picker.
- **No first-time empty-DB experience.** Add a dismissible "Get started" checklist on dashboard when key counts are zero: connect Jobber, invite teammates, add first vendor, set spend budget.

### Mobile-hostile field pages

- `/clients`, `/today`, `/operations/*` use `px-8 py-12` with no `sm:` step-down and 4-5 column tables. Field workers on phones overflow horizontally. Switch wrappers to `px-4 sm:px-8 py-6 sm:py-12` and use card-list-on-small-screens (`md:hidden` / `hidden md:table`).

### Inconsistent patterns

- Three create-UX patterns coexist (inline form, dedicated `/new` page, dialog). Pick one per data shape and refactor the outliers (`/operations/employees`, `/operations/budgets` use inline; everything else uses dedicated pages or dialogs).
- List pages missing empty states (`/clients`, `/today`, `/operations/*`). Copy the `/jobs` empty-state pattern.

### Notification + feedback follow-through

- Admin status change on `/admin/feedback` doesn't notify the submitter. Insert a notification on status change; add a `/feedback/[id]` detail view and wire `RESOURCE_HREFS.feedback`.
- Recurring tasks spawned by cron have no breadcrumb back to their rule. Surface "Created by recurring rule: \<name\>" on `/tasks/[id]`.
