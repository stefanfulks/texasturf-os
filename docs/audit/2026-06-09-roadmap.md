## 3. Structural patterns that drove the audit

Three patterns showed up across multiple dimensions. The fixes above stop the bleeding; the cleanup that finishes them lives in section 5.

1. **"Service-role = safe in server components" mental model** infected `src/lib/warehouse/` and a few user-facing pages. Fixed: role gates added to every warehouse mutation, plus `/clients`, `/today`, `/operations/[id]` mobile-friendly chrome. **Remaining cleanup:** convert the actual DB writes from `supabaseAdmin()` to user-context client now that types regen unblocks them. Same for `queries.ts` read helpers.
2. **Schema drift.** `database.types.ts` is stale ~15 migrations. **Remaining cleanup:** one `gen types` command (manual step 3 above), then drop `as unknown as never` casts in dashboard, fleet, tasks.
3. **Shipped-but-orphaned features.** Fixed: Operations, Clients, Today, Recurring, Admin pages now in UserMenu. **Remaining:** detail pages, cross-module composition, role-aware nav, onboarding redirect — all listed below.

## 4. What's left — feature design work

Everything below is real feature work (new pages, schema changes, UX decisions) rather than fixes. Sequence is suggestion only.

### Auth boundary cleanup (needs types regen first)

- **Convert `/clients`, `/today`, `/operations/tools/[id]`, `/operations/vehicles/[id]` reads from `supabaseAdmin()` to user-context client.** Tables involved have authenticated SELECT policies already, so no data exposure changes — pure hygiene.
- **Refactor `src/lib/warehouse/queries.ts` to take a `SupabaseClient` param.** Callers pass user-context client. Same data exposure today; defense-in-depth posture afterward.
- **`/admin/users` invite rollback errors** — currently `.catch(() => {})` swallows orphaned-auth-user cleanup failures. Add `Sentry.captureException` in the rollback catch.
- **Drop `profiles.google_*_token` columns** in a follow-up migration once Vercel logs show no traffic on the old read path (destructive DDL — needs explicit approval).

### Feature pages

- **`/clients/[id]` detail view** — show client + their Jobber jobs + visits + linked OS invoices, plus "Create task about this client" and "Open in Jobber" deep-link.
- **`/today` per-visit actions** — make each row a Link to `/today/[visit_id]` (or `/install/[id]` already exists per the parallel session's work), add "Mark complete" action that calls Jobber's mutation + updates `jobber_visits.is_complete`, resolve `assigned_user_ids` to profile names.
- **`/feedback/[id]` detail view** — pair with the notification-bell wiring already in place. On admin status change in `/admin/feedback`, insert a notification referencing the feedback.

### Cross-module composition

- **Jobs (`projects`) ↔ Jobber Jobs.** Add `jobber_job_id` on projects (or a join table) and a "Link to Jobber job" picker on `/jobs/[id]`. On webhook `JOB_COMPLETE`, advance the linked project to `ready_for_review` and optionally auto-create an Invoice draft.
- **Invoice ↔ Project FK.** Add `project_id` (uuid FK) to `invoices`; surface "Invoices for this job" on `/jobs/[id]`. Emit a notification on approve/paid.
- **Meetings on dashboard + today.** "Meetings today" tile on the dashboard at-a-glance row; merge today's meeting occurrences into `/today`'s timeline alongside Jobber visits.
- **Unified `/agenda`** that interleaves Google events + Jobber visits + meeting occurrences + due tasks. Keep the source-specific pages (`/calendar`, `/meetings`) for management.
- **Inventory + Operations dashboards merge.** They duplicate each other. Pick one as the home; surface the other as a tab.
- **Recurring rule breadcrumb on task** — "Created by recurring rule: \<name\>" on `/tasks/[id]` with a link to `/tasks/recurring#<rule_id>`.

### Onboarding + role-aware UX

- **Onboarding redirect.** In `(app)/layout.tsx` after profile fetch, redirect to `/onboarding/department` when `departments.length === 0` and pathname isn't already in `/onboarding/*`. Then remove the inline picker from `/dashboard`.
- **First-time get-started checklist.** Dismissible "Connect Jobber / Invite teammate / Add vendor / Set budget" tile on the dashboard when key counts are zero. Persist dismissed state on profile.
- **Role-aware nav.** Pass `departments` from `(app)/layout.tsx` to `NavLinks` and filter `PERSONAL_TABS_BASE` by them. Field-only: Today/Tasks/Vehicles/Calendar/Turfy. Office: Invoices/Tasks/Meetings/Calendar/Attention. Admin: full.

### Turfy tool expansion

- **Add read tools** for: `search_clients` (jobber_clients), `search_jobs` (projects + jobber_jobs union), `get_today_schedule` (jobber_visits + meeting occurrences + calendar), `search_meetings`, `get_fleet_availability`. Keep all read-only with RLS.

### Code consistency

- **Pick one create-UX pattern per data shape.** Today three coexist (inline form, dedicated `/new` page, dialog). Refactor outliers (`/operations/employees`, `/operations/budgets` use inline; everything else dedicated or dialog).
- **PostHog business events.** Today only `$pageview` is captured. Either wire `invoice_submitted`, `task_created`, `assistant_query`, etc., or remove the dep.
- **Sentry source-map upload.** Confirm `SENTRY_AUTH_TOKEN` is set in Vercel Production env after the `.env.example` template update.
- **`src/lib/supabase/admin.ts`** is now obsolete (warehouse + Jobber types are in the regen). Finish the TODO and delete the file.

### Env hygiene

- **`.env.production` exists on disk with live Supabase service-role + Resend keys.** Gitignored, but local-machine blast radius is real. Move all values to Vercel env (Production scope), use `vercel env pull` for local prod debugging, then delete the file. Rotate any key that may have been shared.
